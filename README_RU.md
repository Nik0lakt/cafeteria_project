# Cafeteria — Система управления корпоративной столовой

Полноценная B2B-платформа для автоматизации корпоративного питания. Объединяет идентификацию по NFC-карте, проверку лица в реальном времени и систему ролевых дотаций — всё управляется через единую административную панель и Telegram-бота.

## Обзор системы

Cafeteria исключает ошибки кассира и нецелевое использование дотаций, полностью автоматизируя процесс оплаты обеда:

1. Сотрудник прикладывает NFC-карту → система загружает профиль
2. Проверка лица через веб-камеру (face_recognition + MediaPipe) → личность подтверждена
3. Расчёт дотации и персонального лимита в реальном времени → оплата проведена
4. Сотруднику отправляется чек в Telegram; администратору — аудит-отчёт (при ручном подтверждении)

Платформа поддерживает несколько POS-терминалов с независимыми меню. Все финансовые расчёты ведутся в целых копейках (BigInt) без риска погрешности плавающей точки.

## Ключевые возможности

### Биометрическая оплата (Face ID)

- Проверка "живости" лица по видеопотоку с веб-камеры — защита от использования распечатанных фотографий
- Биометрические эмбеддинги хранятся как JSON-векторы — без pickle-файлов, без бинарных блобов
- Ручной резервный режим: кассир сравнивает фото из базы с текущим кадром с камеры
- Сессионный поток: каждая попытка оплаты создаёт запись `LivenessSession`, привязанную к UID карты

### Поддержка нескольких терминалов

- Неограниченное количество касс, каждая со своим логином и паролем
- Индивидуальные каталоги товаров на каждом терминале: разные меню для разных точек
- Отдельные категории товаров на каждой кассе
- Статистика с фильтрацией по терминалу в панели администратора

### Система дотаций по ролям

- Размер дневной дотации задаётся для каждой роли (например, Рабочий: 150 ₽/день, Менеджер: 200 ₽/день)
- Дотация начисляется только в рабочие дни согласно индивидуальному графику сотрудника
- Если сумма заказа превышает остаток дневной дотации, разница списывается из месячного лимита
- День обновления месячного лимита настраивается для каждого сотрудника (по умолчанию: 28-е число)
- Все балансы хранятся в копейках (BigInt) для точных вычислений

### Telegram-бот

- Сотрудники проверяют остаток дневной дотации и месячного лимита командой `/my`
- Мгновенный чек об оплате после каждой успешной транзакции
- Администратор получает двойной фото-отчёт (фото из базы + текущий кадр с камеры) при каждом ручном подтверждении
- Бот работает как фоновый поток опроса рядом с сервером FastAPI

### Административная панель

- Одностраничное приложение (SPA), защищённое JWT (HS256, сессии на 8 часов, ежедневная ротация)
- Управление сотрудниками: создание, редактирование, удаление; загрузка или съёмка биометрических фото
- Персональный календарь рабочих дней с пресетами смен (5/2, 2/2, свой режим)
- Управление ролями и размерами дотаций
- График выручки с фильтрами по периоду, терминалу и способу оплаты
- Экспорт истории транзакций в CSV
- Подключение RFID-сканера (Web Serial API) с полем для тестирования UID

### Личный кабинет сотрудника

- Веб-вход по адресу `/cabinet.html` — авторизация по персональному паролю
- Просмотр текущего месячного лимита, дневной дотации и расходов за сегодня
- Смена пароля при первом входе

## Стандарты безопасности

| Контроль | Реализация |
|---|---|
| **Аутентификация** | JWT HS256 через `python-jose`; срок действия 8 часов; ежедневная инвалидация сессии при повторном входе |
| **Хеширование паролей** | bcrypt через `passlib`/`bcrypt`; отдельные хеши для сотрудников и администратора |
| **Финансовая точность** | Все денежные значения хранятся как `BIGINT` копейки; плавающая точка не используется в платёжных путях |
| **Биометрические данные** | 128-мерные векторы хранятся как `JSON`; pickle-сериализация не применяется |
| **Изоляция БД** | PostgreSQL работает внутри Docker-сети bridge; не доступен с хоста |
| **Валидация входных данных** | Pydantic-схемы на всех эндпоинтах записи; проверка на пустые поля при создании сотрудника |
| **Аудит** | Ручные оплаты вызывают отправку двойного фото-отчёта в Telegram-чат администратора |

## Архитектура

```
Браузер (Chrome)
    │
    ├── Web Serial API ──► Arduino/PN532 (RFID-считыватель)
    │
    └── HTTPS ──► Caddy (обратный прокси, TLS-терминация)
                      │
                      └── FastAPI (Uvicorn, порт 8000)
                              │
                              ├── /api/auth      — аутентификация сотрудников и администратора, JWT
                              ├── /api/liveness  — управление сессиями верификации лица
                              ├── /api/payment   — обработка заказов, расчёт дотации
                              ├── /api/bot       — опрос Telegram-бота (фоновый поток)
                              │
                              └── PostgreSQL (Docker bridge-сеть)
```

**Live-sync разработка**: папки `app/` и `static/` примонтированы как Docker Volume — изменения в коде применяются без пересборки образа.

## Схема базы данных

| Таблица | Назначение |
|---|---|
| `employees` | ФИО, роль, Telegram ID, биометрический эмбеддинг (JSON), месячный лимит (копейки), день обновления лимита, логин/хеш пароля |
| `cards` | Связывает UID NFC-карты с ID сотрудника |
| `transactions` | История платежей: общая сумма, часть дотации, часть лимита, способ оплаты, состав заказа (JSON), ID кассы |
| `role_settings` | Размер дневной дотации для каждой роли |
| `work_days` | Рабочие дни каждого сотрудника (влияет на право получения дотации) |
| `cash_desks` | Логин терминала, описание, хеш пароля |
| `categories` | Категории товаров, привязанные к кассе |
| `products` | Название товара и базовая цена |
| `cash_desk_products` | Переопределение цен товаров для конкретного терминала |
| `liveness_sessions` | Краткосрочные записи сессий верификации лица |

## Установка и запуск

### Требования

- Docker Engine 24+
- Docker Compose v2
- Браузер Chrome или Edge (требуется Web Serial API для RFID)

### 1. Клонирование и настройка

```bash
git clone <url-репозитория>
cd cafeteria_project
cp .env.example .env
```

### 2. Генерация секретов

```bash
# JWT-секрет (минимум 32 символа)
python3 -c "import secrets; print(secrets.token_hex(32))"

# Хеш пароля администратора
python3 -c "from passlib.hash import bcrypt; print(bcrypt.hash('ваш_пароль'))"
```

Заполните `.env` полученными значениями (см. раздел [Переменные окружения](#переменные-окружения)).

### 3. Сборка и запуск

```bash
docker compose up -d --build
```

Приложение будет доступно по адресам:
- `http://localhost:8000` — прямое подключение (без TLS)
- Настроенный домен Caddy — с автоматическим HTTPS

### 4. Первый запуск

При первом старте `main.py` автоматически выполняет миграции схемы через `update_db_schema()` — никаких ручных шагов не требуется.

Откройте админ-панель по адресу `/login.html`, введите пароль администратора и:
1. Добавьте роли и установите размеры дотаций
2. Зарегистрируйте сотрудников и привяжите NFC-карты
3. Создайте кассовые терминалы
4. Загрузите биометрические фото сотрудников через камеру в панели или загрузкой файла

## Переменные окружения

Скопируйте `.env.example` в `.env` и заполните все значения:

```env
# Подключение к PostgreSQL (должно совпадать с docker-compose.yml)
DATABASE_URL=postgresql://user:password@db:5432/cafeteria_db

# Telegram-бот (токен получить у @BotFather)
TELEGRAM_BOT_TOKEN=your_telegram_bot_token_here

# ID чата администратора в Telegram для получения аудит-отчётов
ADMIN_CHAT_ID=your_admin_chat_id_here

# Секрет для подписи JWT — минимум 32 случайных символа
JWT_SECRET=change_me_to_a_long_random_secret_key_min_32_chars

# Bcrypt-хеш пароля административной панели
ADMIN_PASSWORD_HASH=$2b$12$replacethiswitharealhashedpassword
```

## Аппаратная часть

**Подключение RFID-считывателя:**

1. Подключите Arduino Uno с модулем PN532 по протоколу I2C
2. Загрузите в Arduino скетч, который считывает UID карты и выводит его в Serial на скорости 9600 бод в формате `HEX_UID\n`
3. Подключите Arduino через USB к компьютеру с Chrome
4. В панели администратора → вкладка «Настройки» → нажмите **«Подключить сканер»** и выберите COM-порт
5. Зелёный индикатор подтверждает подключение; UID автоматически подставляется в активное поле ввода

Система работает и без оборудования — UID можно ввести или вставить вручную.

## Справочник API

Все административные эндпоинты требуют заголовок `Authorization: Bearer <jwt_token>`.

| Метод | Путь | Авторизация | Описание |
|---|---|---|---|
| `POST` | `/api/login` | — | Вход администратора, возвращает JWT |
| `GET` | `/api/employees` | Админ | Список всех сотрудников |
| `POST` | `/api/employees` | Админ | Создание сотрудника и карты |
| `PUT` | `/api/employees/{id}` | Админ | Обновление данных сотрудника |
| `DELETE` | `/api/employees/{id}` | Админ | Удаление сотрудника и всех связанных данных |
| `GET` | `/api/role_settings` | Админ | Список ролей и размеров дотаций |
| `POST` | `/api/role_settings` | Админ | Добавление роли |
| `PUT` | `/api/role_settings` | Админ | Обновление дотации роли |
| `DELETE` | `/api/role_settings/{name}` | Админ | Удаление роли |
| `GET` | `/api/cash_desks` | — | Список терминалов |
| `POST` | `/api/cash_desks` | — | Добавление терминала |
| `DELETE` | `/api/cash_desks/{id}` | — | Удаление терминала |
| `POST` | `/api/start_liveness` | — | Начало сессии верификации лица |
| `POST` | `/api/liveness_frame` | — | Отправка кадра с веб-камеры для анализа |
| `POST` | `/api/pay` | — | Проведение оплаты с дотацией |
| `GET` | `/api/employee_info` | — | Поиск сотрудника по UID карты |
| `GET` | `/api/statistics/chart` | — | Данные графика выручки (с фильтрами) |
| `GET` | `/api/statistics/export` | — | Экспорт в CSV |
